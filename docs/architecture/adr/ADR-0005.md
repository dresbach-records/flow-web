# ADR-0005 — Política de Zero Mock / Zero Static funcional

- **Status:** Aceito (regra normativa)
- **Data:** 2026-09-05

## Contexto
A "REGRA DE CONCLUSÃO FLOW" e o TODO.MD proíbem mock/fake/static funcional.

## Problema
Garantir que a UI reflita o estado real do backend sem esconder lacunas.

## Opções
1. Permitir mocks para acelerar.
2. Proibir mocks e exibir estados vazios honestos.
3. Mocks controlados por flag.

## Decisão
**Opção 2 — zero mock, zero static funcional.** Se não há backend/API/persistência, a tela mostra `LoadingState`/`EmptyState`/`ErrorState` honestos (ex.: `R$ 0,00`, "—", placeholders com aviso de Fase 9).

## Consequências
- Positivas: confiança, testes significativos, sem enganar usuários.
- Negativas: features incompletas ficam visíveis como incompletas.
- Nota: conteúdo editorial/ilustração (site, hero, catálogos) não é "dado de negócio" e permanece estático.

## Alternativas rejeitadas
- Mocks por flag: criaria estado duplo e risco de vazar para produção.
