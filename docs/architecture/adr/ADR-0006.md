# ADR-0006 — Padrão de componente por pasta

- **Status:** Aceito
- **Data:** 2026-09-05

## Contexto
Componentes duplicados e páginas monolíticas eram problema (auditoria histórica).

## Problema
Definir o padrão de organização de componentes.

## Opções
1. Arquivos soltos (monolíticos).
2. Pasta por componente: `Component.tsx + .css + .types.ts + index.ts`.
3. CSS global centralizado.

## Decisão
**Opção 2** — componente com responsabilidade, interface (types), CSS e exportação próprios:

```
Component/
├── Component.tsx
├── Component.css
├── Component.types.ts
└── index.ts
```

## Consequências
- Positivas: reuso, testabilidade, manutenção.
- Negativas: mais arquivos (gerenciado com barrels).
- Dívida residual: alguns componentes single-file a migrar.

## Alternativas rejeitadas
- CSS global por componente: acoplamento e colisões.
