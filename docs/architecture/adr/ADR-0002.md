# ADR-0002 — Autenticação client-side como canônica

- **Status:** Aceito
- **Data:** 2026-09-05

## Contexto
O backend tem `POST /api/v1/auth/login` que sempre retorna 401 (`USE_FIREBASE_CLIENT_AUTH`).

## Problema
Decidir onde vive o fluxo de login/registro.

## Opções
1. Login server-side (backend cria token próprio).
2. Login client-side via Firebase Auth (canônico), backend valida ID token.
3. Ambos.

## Decisão
**Opção 2 — client-side Firebase Auth como canônico.** O frontend autentica via Firebase SDK; o backend valida o ID token em `requireAuth`. O endpoint `login` do backend permanece desativado por design.

## Consequências
- Positivas: regras do Firestore funcionam com token nativo; menos superfície de ataque; simplicidade.
- Negativas: fluxos que exigem backend (ex.: revogação global de sessões) são limitados.
- Mitigação futura: adicionar provedores/2FA sem trocar o mecanismo.

## Alternativas rejeitadas
- Login server-side: duplicaria identidade e token, complicando as rules.
