# ADR-0004 — Firestore Rules como fronteira de autorização

- **Status:** Aceito
- **Data:** 2026-09-05

## Contexto
O frontend usa `PermissionGuard` para UX; a proteção real precisa ser no servidor.

## Problema
Definir a camada autoritativa de autorização.

## Opções
1. Só frontend.
2. Só backend Express.
3. Firestore Rules como autorização real + backend `requireAdmin` para rotas privilegiadas + frontend apenas como UX.

## Decisão
**Opção 3.** As Firestore Rules (min-privilege, `isOwner`/`isAdmin`, `affectedKeys`) protegem os dados; `requireAuth`/`requireAdmin` protegem a API; `PermissionGuard` é cosmético.

## Consequências
- Positivas: dados protegidos mesmo com cliente comprometido; auditoria.
- Negativas: regras precisam ser mantidas em sincronia com o código.
- Mitigação: matriz de regras documentada e testes com emulador planejados.

## Alternativas rejeitadas
- Frontend-only: inseguro.
- Backend-only para tudo: duplicaria a lógica e atrasaria o produto.
