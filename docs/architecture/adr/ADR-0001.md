# ADR-0001 — Firebase como infraestrutura central

- **Status:** Aceito
- **Data:** 2026-09-05

## Contexto
A FLOW precisa de auth, banco de dados, storage e analytics sem reconstruir infra do zero.

## Problema
Escolher a base de persistência e autenticação que suporte evolução sem reescrita.

## Opções
1. Backend próprio completo (Postgres + Redis + filas) desde o início.
2. Firebase (Auth + Firestore + Storage) como infraestrutura.
3. Hibrido: Firebase + backend Express complementar.

## Decisão
Adotar a **opção 3 (híbrido)**:
- Firebase é a infraestrutura central (auth, dados, mídia).
- Backend Express complementa para operações privilegiadas (notify, push, guardian, scheduler, contato, relatórios).
- Regras de segurança no Firestore são a autorização real.

## Consequências
- Positivas: velocidade, escalabilidade gerenciada, regras de segurança declarativas.
- Negativas: dependência de plataforma; custo de leituras; N+1 exige disciplina.
- Mitigação: `services/` como fronteira única, permitindo migração incremental.

## Alternativas rejeitadas
- Backend-first: atrasaria o produto sem necessidade.
- Postgres desde já: complexidade prematura para o grafo atual.
