# ADR-0010 — Evolução: Modular Monolith → serviços (sem microserviços prematuros)

- **Status:** Aceito
- **Data:** 2026-09-05

## Contexto
A FLOW crescerá de app pequeno para rede social de grande escala.

## Problema
Definir a estratégia de escala sem reescrever o sistema.

## Opções
1. Microserviços desde o início.
2. Modular monolith + Firebase, evoluindo por extração justificada.
3. Monólito gigante sem separação.

## Decisão
**Opção 2** — manter módulos bem separados no monólito atual (frontend modular, backend Express + Firebase). Extrair serviços somente com justificativa (escala, isolamento, ownership, deploy, performance, disponibilidade, segurança), na ordem: cache (Redis) → filas/workers → feed/notify/search.

## Consequências
- Positivas: velocidade de entrega, baixa complexidade inicial, caminho claro.
- Negativas: exige disciplina de limites de módulo e observabilidade.
- Mitigação: ADRs a cada extração; contratos estáveis.

## Alternativas rejeitadas
- Microserviços desde o início: complexidade operacional sem ganho no estágio atual.
- Monólito sem separação: dificultaria a evolução futura.
