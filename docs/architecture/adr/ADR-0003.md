# ADR-0003 — Roteador manual (history API) em vez de React Router

- **Status:** Aceito
- **Data:** 2026-09-05

## Contexto
`src/App.tsx` implementa roteamento manual com `history.pushState` + `popstate`.

## Problema
Escolher o mecanismo de roteamento da SPA.

## Opções
1. React Router (biblioteca padrão).
2. Roteador manual (history API).
3. Biblioteca alternativa.

## Decisão
**Opção 2 — roteador manual** para o escopo atual, com resolução explícita por prefixo (auth/admin/memorial/site/app) e `React.lazy` para code-splitting.

## Consequências
- Positivas: controle total, zero dependência extra, code-splitting limpo por rota.
- Negativas: sem features avançadas (loaders, nested routes, query parsing tipado).
- Mitigação: se a complexidade de rotas crescer, migrar para React Router como roteador de baixo nível mantendo o `ModuleGate` e a resolução atual.

## Alternativas rejeitadas
- React Router desde o início: adicionaria dependência sem benefício imediato.
